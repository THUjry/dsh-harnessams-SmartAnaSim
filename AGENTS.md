# AGENTS.md — HarnessAMS-SmartAnaSim

> Rules for AI agents and human maintainers working in this repo. Read this file before changing anything here. This repo keeps English-only, self-contained content (no references to files outside the repo).

- Package `dsh-harnessams-smart-ana-sim` / row id `harnessams-smart-ana-sim`, version 0.1.0; `engines.dsh` locks the verified DSH version. The plugin has **no runtime `@deepseek-ai/dsh-*` dependency**: tool definitions are built by the local schema compiler in `src/tool.js` (see "Tool schema" below). Sole dependency (runtime `dependencies`, 2026-11-01): `@deepseek-ai/schemastery` for the Config family toggles — installed bundles do not get devDependencies and schemastery is not a host-provided peer, so peer+dev would fail to resolve in installed form (same placement rule the retired `dsh-remote` used; `tests/entry.test.mjs` guards it).
- **Tool surface (5, simulator-only)**: `spectre_assemble` / `spectre_run_sweep` / `spectre_parse`; `snp_read` / `snp_extract`. The generic remote batch channel (`batch_*`, renamed from `bsub_*` on 2026-11-09) and the simulator-agnostic analysis tools (`sim_analysis` / `sim_progress` / `safe_trash`) moved to the top-level `dsh-harnessams` plugin on 2026-11-01 — this package ships simulator-specific code only. The breaking renames from `sim_assemble` / `sim_run_sweep` carry no aliases (0.1.0 was never published). **The ngspice family was removed on 2026-11-02** (sky130 runs in Spectre after model transcription; ngspice carried only demo value) — the pre-removal state lives in this repo's `ngspice` branch.
- **Layout**: plugin source under `src/` (entry `src/index.js`, plain JS, no build chain), runtime Python under `scripts/{common,spectre,snp}/`, the numpy-fallback backend under `assets/`, tests under `tests/` (bare `node --test` from the repo root; a directory argument fails on Node 24). Every script filename carries its family prefix (`common_*`, `spectre_*`, `snp_*`); keep it that way even inside subdirectories, and keep the unique basenames (a flat remote upload must not collide).
- **Script layer**: scripts are plain files spawned by the Node channel (`python <script> …`). Cross-directory imports insert `scripts/` (the parent of the script's own directory) into `sys.path` and use `from common.common_sweep_engine import …` / `from spectre.spectre_psf_parse import …`. No `__init__.py` (PEP 420 namespace packages). Assembly/check/adjudication logic lives entirely in the script layer; the Node side is a channel only.
- **Language rule** (suite-wide, D-004 in the HarnessAMS repo's `docs/decisions.md`): in-plugin functionality is JS single-implementation by default; this package's Python is confined to the three sanctioned families — remote-runnable sweep workers (e.g. `spectre_sweep_worker.py`), s-parameter numeric computing (e.g. `snp_extract.py`), and per-project user-authored assembly scripts (e.g. `gen_selfcheck_rc.py`, shipped by the top-level plugin's self-check project) — no new Python families beyond these.
- **Shared batch engine** (`scripts/common/common_sweep_engine.py`): `@@PARAM@@` substitution, cross-product/zip combinations, point directories (`00`, `01`, …; plain decimal from 100), atomic `point_meta.json`, `sweep_progress.json` on a 30 s cadence, `.worker_started` / `.compute_node` / `.simulator` markers. Every sweep worker must keep this data contract; simulator-specific command execution and output parsing stay in each worker.
- **Tool schema**: `src/tool.js` compiles the author-facing parameter DSL into an object-rooted JSON Schema. `required` may only be `true` (omit it for optional). The old `required: false` form was the root cause of the `type: null` schema bug (dev-mount could not resolve `@deepseek-ai/dsh-tools` and registered the raw DSL); do not reintroduce it. `entry.test.mjs` asserts every tool's schema, required list, enum and output shape.
- **Family toggles (2026-11-01)**: `src/index.js` exports a schemastery `Config` (`spectre`/`snp` booleans, default `true`; changing the config hot-swaps the plugin — cordis restarts the fiber and re-registers). DSH (0.2.1-rc.2; 0.2.2-rc.1 source-checked 2026-11-10, unchanged) does NOT auto-render a bundle's config as settings-page switches: the plugin manager shows them only when the bundle's browser half registers the `plugins.row.config` slot (key `<package>#<row id>`); this package ships no browser half (deferred by user decision 2026-11-01), so the toggles are edited through the profile config layer. `toolDefinitions(ctx, config)` trims a family only on explicit `false` (`!== false`, so `undefined` never trims); the `~standard` validate hook must stay a real schemastery schema — cordis `resolveConfig` calls it directly on the exported object and a plain object crashes the load. The official `tool-fs` plugin (read/write/edit booleans) is the pattern precedent.
- **Spectre channel (local)**: `spectre_run_sweep` runs on the host executing the plugin; it does not know about dsh-remote. Contract: psfascii output (`output_format: "psfascii"`), `template.scs`, `@@PARAM@@`; command defaults `+lqtimeout 900`, `-maxw 5`, `-maxn 5`, `++aps` (never `+preset aps`; SPECTRE-132), `+mt`, `+logstatus`; smart timeout extends once for `Waiting for available license` and once for existing raw output before killing. Statuses: success (rc 0), partial (rc≠0 with raw output), failure (rc≠0 without), timeout (killed), error (spawn/template). `spectre_psf_parse.py` handles PSF ASCII only (swept/delta/complex/non-swept info); binary PSF is unsupported by design. `spectre_checks.py` owns the `.scs` assembly checks, including the geometry unit-suffix rule (bare number = metres in Spectre) and the ideal R/C/L value-range gate (R 0.1..1M ohm, C 1f..1u farad, L 0.1p..10n henry, inclusive; literals, `@@P@@` swept values and template `parameters` references; `m`/`M` follow Spectre case sensitivity).
- **Generic remote batch channel — MOVED (2026-11-01, remote channel switched to @linxin666/dsh-ssh on 2026-11-14)**: `batch_submit` / `batch_poll` / `batch_fetch` (renamed from `bsub_*` on 2026-11-09; the scheduler value `none` became `direct`) and the remote shell (`src/remote.js`) / LSF engine (`src/batch.js`) now live in the `HarnessAMS` repo (`src/tools/batch.js`, `src/batch.js`, `src/remote.js`; module files renamed from `bsub.js` on 2026-11-10). Their upload tree / worker lookup root is the workspace `harnessams.json` `sim_scripts_dir`, which points at THIS package's `scripts/` directory — the domain contract (`template.scs` convention, remote write fence, `bjobs` `No job found` = completed) moved with them; remote files ride explicit `ssh_upload`/`ssh_download` calls (the dsh-remote mirror transparency is retired — Broadband3-style flows call the transfer tools explicitly); see the HarnessAMS repo's AGENTS.md.
- **snp_***: S-parameter reading/extraction, tools-only (no UI). Numeric backend: numpy primary, `assets/numfallback.py` automatic pure-stdlib fallback (`SNP_FORCE_FALLBACK=1` forces it); both backends share the same upper-level code and must agree (test-asserted). Touchstone v1 ordering: 2-port files are S11,S21,S12,S22; N>2 files are row-major. The coupled_tl theory gate (default 5.0e-2) is calibrated at 4x the validated reference coupler's relative off-block residual; changing it requires recalibration notes. Known port-mapping trap: a through-pair grouping block-diagonalizes perfectly but yields non-physical modal impedances / split thetas — the physicality checks (Re(Z0) resistive-dominant, theta monotonic, theta_e ~= theta_o) must stay.
- **Hard PDK isolation**: PDK paths live only in assembly-layer configuration, never in agent context; the format / dimension / ideal-value-range / bias<Vdd checks reject at the assembly layer, before the simulator. The assembly layer is the only code path that touches PDK files.
- **Safety by default**: destructive operations move paths to the trash folder instead of deleting.
- **Reports — MOVED (2026-11-01)**: `sim_collect` / `sim_progress` / `sim_report` / `sim_trash` and the analysis scripts (`common_collect_results.py` / `common_gen_sweep_report.py` / `common_trash.py`, plus a byte-identical `common_workspace.py` copy) moved to the `HarnessAMS` repo (`src/tools/shared.js` + `src/scripts/common/`). The report hard rules (`var ROUND_DATA`, `<script>` round-data loading, `?v=` cache-bust, utf-8-sig HTML, `el.on` rebind, per-section try/catch) and the `sim_report` task-injection contract moved with them; see the HarnessAMS repo's AGENTS.md.
- **Workspace convention**: a `harnessams.json` is discovered by walking upward (bare form, or inside `harnessams-workspace/`), max 8 levels; relative path fields resolve against the config file's directory; JSON reads tolerate a UTF-8 BOM. Fields used HERE: `pdk_lib`, `spectre_cmd`. The remaining fields (`trash_dir`, `plotly_asset`, `remote_python`, `remote_scripts_dir`, `sim_scripts_dir`) are consumed by the top-level plugin's analysis/batch/report tools; `sim_scripts_dir` points at this package's `scripts/` tree and must keep pointing there (the batch upload tree and the script-sync check both depend on it — the latter walks it recursively against `remote_scripts_dir`).
- **Plotly single copy**: reports seed `<workspace_root>/assets/plotly.min.js` from an explicit `--plotly` path, ancestor candidates (`assets/`, `src/assets/`, an installed `node_modules/dsh-harnessams/assets/`, `dsh-harnessams/assets/`), or the workspace `plotly_asset` field; the CDN is the fallback (`--plotly-cdn` forces it). Never ship a Plotly copy in this package. (The report generator itself moved to the top-level plugin; the rule moves with it.)
- **Tests**: `node --test` from the repo root (31 tests) covers tool metadata/schema/validation, recursive script parsing + filename prefixes, PSF parsing (`tests/data/psf`), the Spectre worker mechanics with a fake process layer (`tests/spectre_worker_test.py`), the assembly checks including the ideal RCL ranges (`tests/spectre_checks_test.py`), the S-parameter regression suite (`tests/data`) and the JS tool-face contracts (snp summary/exit-1); the batch-channel and report-injection tests moved to the HarnessAMS repo with the tools. Python self-tests run as plain scripts and use `python -B` so they never write `__pycache__` into the repo. `tests/manual/compare_spectre_runs.py` is the node1 foreground-vs-batch acceptance helper (not shipped).
- **Validation record (2026-10-31)**: demo1 ngspice single-point rerun matched the recorded metrics bit-for-bit; node1 dual-mode Spectre (Broadband4 Round1 template, 2 states at 65 C) was later re-run **through the plugin tools only** — `bsub_submit(scheduler="none")` on node1 (`direct-1793437388485`) and `bsub_submit(scheduler="lsf")` as Job 15929901 on node5 both returned 2/2 success; `bsub_fetch` recovered both point metas and `sp.sp` files, each pair differing only in the PSF header `date`, and `snp_read` produced identical numeric CSV rows. The earlier ssh-only run (Job 15924601) remains reproducible with `tests/manual/compare_spectre_runs.py`.
- Runtime artifacts (netlists, simulation outputs, report intermediates) are written into the demo project's run directories (`sweep/Round*/top/<NN>/`), never committed; scripts resolve paths from the workspace `harnessams.json` to survive CWD drift.
- Fixture hygiene (2026-11-12): tests and docs never carry real cluster account tokens, private-net IPs, local drive paths or the dev machine name — use the neutral placeholders (`op`, `test_user`, documentation-range `192.0.2.x` IPs, `D:/proj/...`); the repo's history was scrubbed to these placeholders on 2026-11-12. A local pre-commit hook under `.git/hooks/` (untracked; recreate it after a fresh clone) rejects staged content matching those families.
- Commits: local commits are at the agent's discretion (no per-commit approval needed); **pushing is always manual** — automated flows must never push. Messages in English (`<verb> <scope>: <summary>`), one topic per commit.
