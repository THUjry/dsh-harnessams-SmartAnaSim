# AGENTS.md — HarnessAMS-SmartAnaSim

> Rules for AI agents and human maintainers working in this repo. Read this file before changing anything here. This repo keeps English-only, self-contained content (no references to files outside the repo).

- Package `dsh-harnessams-smart-ana-sim` / row id `harnessams-smart-ana-sim`, version 0.1.0; `engines.dsh` locks the verified DSH version. The plugin has **no runtime `@deepseek-ai/dsh-*` dependency**: tool definitions are built by the local schema compiler in `src/tool.js` (see "Tool schema" below).
- **Tool surface (7, simulator-only)**: `ngspice_assemble` / `ngspice_run_sweep`; `spectre_assemble` / `spectre_run_sweep` / `spectre_parse`; `snp_read` / `snp_extract`. The generic remote batch channel (`bsub_*`) and the simulator-agnostic analysis tools (`sim_collect` / `sim_progress` / `sim_report` / `sim_trash`) moved to the top-level `dsh-harnessams` plugin on 2026-11-01 — this package ships simulator-specific code only. The breaking rename from `sim_assemble` / `sim_run_sweep` has no aliases (0.1.0 was never published).
- **Layout**: plugin source under `src/` (entry `src/index.js`, plain JS, no build chain), runtime Python under `scripts/{common,ngspice,spectre,snp}/`, the numpy-fallback backend under `assets/`, tests under `tests/` (bare `node --test` from the repo root; a directory argument fails on Node 24). Every script filename carries its family prefix (`common_*`, `ngspice_*`, `spectre_*`, `snp_*`); keep it that way even inside subdirectories, and keep the unique basenames (a flat remote upload must not collide).
- **Script layer**: scripts are plain files spawned by the Node channel (`python <script> …`). Cross-directory imports insert `scripts/` (the parent of the script's own directory) into `sys.path` and use `from common.common_sweep_engine import …` / `from spectre.spectre_psf_parse import …`. No `__init__.py` (PEP 420 namespace packages). Assembly/check/adjudication logic lives entirely in the script layer; the Node side is a channel only.
- **Shared batch engine** (`scripts/common/common_sweep_engine.py`): `@@PARAM@@` substitution, cross-product/zip combinations, point directories (`00`, `01`, …; plain decimal from 100), atomic `point_meta.json`, `sweep_progress.json` on a 30 s cadence, `.worker_started` / `.compute_node` / `.simulator` markers. Both workers must keep this data contract; simulator-specific command execution and output parsing stay in each worker.
- **Tool schema**: `src/tool.js` compiles the author-facing parameter DSL into an object-rooted JSON Schema. `required` may only be `true` (omit it for optional). The old `required: false` form was the root cause of the `type: null` schema bug (dev-mount could not resolve `@deepseek-ai/dsh-tools` and registered the raw DSL); do not reintroduce it. `entry.test.mjs` asserts every tool's schema, required list, enum and output shape.
- **Spectre channel (local)**: `spectre_run_sweep` runs on the host executing the plugin; it does not know about dsh-remote. Contract: psfascii output (`output_format: "psfascii"`), `template.scs`, `@@PARAM@@`; command defaults `+lqtimeout 900`, `-maxw 5`, `-maxn 5`, `++aps` (never `+preset aps`; SPECTRE-132), `+mt`, `+logstatus`; smart timeout extends once for `Waiting for available license` and once for existing raw output before killing. Statuses: success (rc 0), partial (rc≠0 with raw output), failure (rc≠0 without), timeout (killed), error (spawn/template). `spectre_psf_parse.py` handles PSF ASCII only (swept/delta/complex/non-swept info); binary PSF is unsupported by design. `spectre_checks.py` owns the `.scs` assembly checks, including the geometry unit-suffix rule (bare number = metres in Spectre).
- **Generic remote batch channel — MOVED (2026-11-01)**: `bsub_submit` / `bsub_poll` / `bsub_fetch` and the dsh-remote shell (`src/remote.js`) / LSF engine (`src/bsub.js`) now live in the `HarnessAMS` repo (`src/tools/bsub.js`, `src/bsub.js`, `src/remote.js`). Their upload tree / worker lookup root is the workspace `harnessams.json` `sim_scripts_dir`, which points at THIS package's `scripts/` directory — the whole domain contract (borrowed `{ id, session }` live session, `promoteOnTimeout: false`, `template.scs` convention, remote write fence, `bjobs` `No job found` = completed) moved with them; see the HarnessAMS repo's AGENTS.md.
- **snp_***: S-parameter reading/extraction, tools-only (no UI). Numeric backend: numpy primary, `assets/numfallback.py` automatic pure-stdlib fallback (`SNP_FORCE_FALLBACK=1` forces it); both backends share the same upper-level code and must agree (test-asserted). Touchstone v1 ordering: 2-port files are S11,S21,S12,S22; N>2 files are row-major. The coupled_tl theory gate (default 5.0e-2) is calibrated at 4x the validated reference coupler's relative off-block residual; changing it requires recalibration notes. Known port-mapping trap: a through-pair grouping block-diagonalizes perfectly but yields non-physical modal impedances / split thetas — the physicality checks (Re(Z0) resistive-dominant, theta monotonic, theta_e ~= theta_o) must stay.
- **Hard PDK isolation**: PDK paths live only in assembly-layer configuration, never in agent context; the format / dimension / bias<Vdd checks reject at the assembly layer, before the simulator. The assembly layer is the only code path that touches PDK files.
- **Safety by default**: destructive operations move paths to the trash folder instead of deleting.
- **Reports — MOVED (2026-11-01)**: `sim_collect` / `sim_progress` / `sim_report` / `sim_trash` and the analysis scripts (`common_collect_results.py` / `common_gen_sweep_report.py` / `common_trash.py`, plus a byte-identical `common_workspace.py` copy) moved to the `HarnessAMS` repo (`src/tools/shared.js` + `src/scripts/common/`). The report hard rules (`var ROUND_DATA`, `<script>` round-data loading, `?v=` cache-bust, utf-8-sig HTML, `el.on` rebind, per-section try/catch) and the `sim_report` task-injection contract moved with them; see the HarnessAMS repo's AGENTS.md.
- **Workspace convention**: a `harnessams.json` is discovered by walking upward (bare form, or inside `harnessams-workspace/`), max 8 levels; relative path fields resolve against the config file's directory; JSON reads tolerate a UTF-8 BOM. Fields used HERE: `ngspice_cmd`, `pdk_lib`, `spectre_cmd`. The remaining fields (`trash_dir`, `plotly_asset`, `remote_python`, `remote_scripts_dir`, `sim_scripts_dir`) are consumed by the top-level plugin's analysis/batch/report tools; `sim_scripts_dir` points at this package's `scripts/` tree and must keep pointing there (the bsub upload tree and the script-sync check both depend on it — the latter walks it recursively against `remote_scripts_dir`).
- **Plotly single copy**: reports seed `<workspace_root>/assets/plotly.min.js` from an explicit `--plotly` path, ancestor candidates (`assets/`, `src/assets/`, an installed `node_modules/dsh-harnessams/assets/`, `dsh-harnessams/assets/`), or the workspace `plotly_asset` field; the CDN is the fallback (`--plotly-cdn` forces it). Never ship a Plotly copy in this package. (The report generator itself moved to the top-level plugin; the rule moves with it.)
- **sky130 conventions** (ngspice): use the fossi-foundation **continuous** `combined_models` models; w/l are written internally as bare um values (the model library sets `scale=1u`); user input with u/n suffixes is normalized at the assembly layer; MOS instances use the X prefix; MC's `.option seed` precedes `.lib`.
- **Tests**: `node --test` from the repo root (30 tests) covers tool metadata/schema/validation, recursive script parsing + filename prefixes, PSF parsing (`tests/data/psf`), ngspice/Spectre worker mechanics with fake process layers (`tests/*_worker_test.py`), and the S-parameter regression suite (`tests/data`); the bsub-channel and report-injection tests moved to the HarnessAMS repo with the tools. Python self-tests run as plain scripts and use `python -B` so they never write `__pycache__` into the repo. `tests/manual/compare_spectre_runs.py` is the node1 foreground-vs-bsub acceptance helper (not shipped).
- **Validation record (2026-10-31)**: demo1 ngspice single-point rerun matched the recorded metrics bit-for-bit; node1 dual-mode Spectre (Broadband4 Round1 template, 2 states at 65 C) was later re-run **through the plugin tools only** — `bsub_submit(scheduler="none")` on node1 (`direct-1793437388485`) and `bsub_submit(scheduler="lsf")` as Job 15929901 on node5 both returned 2/2 success; `bsub_fetch` recovered both point metas and `sp.sp` files, each pair differing only in the PSF header `date`, and `snp_read` produced identical numeric CSV rows. The earlier ssh-only run (Job 15924601) remains reproducible with `tests/manual/compare_spectre_runs.py`.
- Runtime artifacts (netlists, simulation outputs, report intermediates) are written into the demo project's run directories (`sweep/Round*/top/<NN>/`), never committed; scripts resolve paths from the workspace `harnessams.json` to survive CWD drift.
- Commits require an explicit user request or authorization.
