# AGENTS.md — HarnessAMS-SmartAnaSim

> Rules for AI agents and human maintainers working in this repo. Read this file before changing anything here. This repo keeps English-only, self-contained content (no references to files outside the repo).

- Package `dsh-harnessams-smart-ana-sim` / row id `harnessams-smart-ana-sim`, version 0.1.0; `engines.dsh` locks the verified DSH version. The plugin has **no runtime `@deepseek-ai/dsh-*` dependency**: tool definitions are built by the local schema compiler in `src/tool.js` (see "Tool schema" below). Sole runtime dependency (`dependencies`): `@deepseek-ai/schemastery` for the Config family toggles — installed bundles do not get devDependencies and schemastery is not a host-provided peer, so peer+dev would fail to resolve in installed form (same placement rule the retired `dsh-remote` used; `tests/entry.test.mjs` guards it).
- **Positioning**: this package is a PURE TOOL SET, usable on its own — no other plugin required, and no reference to any other plugin's tools in tool descriptions, file headers or skill text. The spectre side is netlist pre-check for hand-written run directories (the assembly tool face is retired; scripted assembly via a project `gen_*.py` is the optional legacy path); sweep execution and routine result parsing are script-face (data processing is not tool-shaped) — the single sanctioned exception is `post_check`: on-demand data-integrity DIAGNOSIS is tool-shaped (collect-style, report-only, zero file artifacts); the managed scan flow (submission, monitoring, result retrieval) lives in the HarnessAMS suite's batch channel, which drives this package's workers through the workspace `sim_scripts_dir`.
- **Tool surface (7)**: `spectre_pre_check` (pure-JS netlist pre-check — see the spectre-channel bullet); `snp_guide` (always declared) + `snp_read` / `snp_extract` (deferred, guide-gated — see the snp_* bullet); `gen_vsch_import` / `gen_vsch_export` (Virtuoso schematic interaction, see the vsch bullet); `post_check` (on-demand collect-style data-integrity diagnostics — see the post bullet). The `spectre_assemble` / `spectre_run_sweep` / `spectre_parse` / `ngspice_*` tool faces are retired — their work is script-face, the optional legacy gen-script path, or the pre-check engine.
- **vsch family**: `gen_vsch_import` / `gen_vsch_export` assemble ready-to-run TEXT for the netlist <-> OpenAccess round trip — pure JS string assembly in `src/tools/vsch.js`, never executes anything, never writes files (cds.lib layout / install roots / license hosts are environment-specific; execution belongs to the caller). Each returns structured schemes (`param`/`cli`/`plain_skill` for import, `si`/`ocean`/`cdlout`/`plain_skill` for export); `plain_skill` = self-contained Cadence SKILL text pasteable into an open CIW, doubling as the F1 fallback when a headless carrier fails. Recipes live in the skill pages `virtuoso-import.md` / `virtuoso-export.md` .
- **Wording rule**: "SKILL language" / "SKILL script" always means the Cadence SKILL language — the language itself, never necessarily a file on disk; lowercase `skill` or the bare word means a DSH plugin skill (like the bundled `smart-spectre`). Applies to README, docs, tool descriptions and skill text.
- **Markdown style rule**: every `.md` file keeps one paragraph per line — no manual hard-wrapping inside a paragraph (repo-wide: README, PUBLISH, docs, bundled skill pages included). Exempt from merging: YAML frontmatter, fenced code blocks, tables, list-marker lines, and intentionally indented command blocks.
- No per-wave development history: this file records current rules only — development history lives in the root repo's stage chronicle, decision evolution in the HarnessAMS repo's `docs/decisions.md`.
- **post family**: `post_check {work_dir | raw_dir}` is the on-demand data-integrity diagnostic — call it when sweep results look wrong, empty or incomplete, never as part of the routine pipeline. Collect-style inversion of the parser's strict rules: every point is scanned (bad points reported, never skipped), every accessor violation is caught and enumerated into one classified JSON report (coverage vs `sweep_progress.json`, exactly-one `*.raw` per point, parse errors, axis realness/monotonicity, NaN delta gaps, `point_meta.signals` scalar rules, parser-dropped VALUE lines, errlog tails; issue cap `--max-issues`). The JS side (`src/tools/post.js`) is pure orchestration — argparse owns the exactly-one input rule, every check lives in `scripts/spectre/spectre_post_check.py`; the report rides in the tool result (zero file artifacts). Not deferred/gated: the usage posture lives in the tool description.
- **Bundled skill**: `skills/smart-spectre/` — root `SKILL.md` (scope: pure command-line simulation + parameter sweeps; index + the Virtuoso round-trip pointer + the bridge-lite external pointer) plus companion pages `spectre-cli.md` (the operational page: direct runs, the write layer and its `spectre_pre_check` contract, run-directory contract, sweep worker + sweep_config schema, psf analysis script, post_check diagnostics, cascade assembly; snp_* tools are out of scope), `spectre-grammar.md` (netlist syntax with a section per analysis type: template `@@PARAM@@` rules, Spectre-vs-SPICE rules and units, AC excitation, sp with `paramtype=yz`, swept PSS configuration), `virtuoso-import.md` (netlist -> OA, incl. the round-trip charter) and `virtuoso-export.md` (OA -> netlist). The `skill` tool renders the body with a base-directory hint but never enumerates the directory — the root page must name every companion file explicitly (`tests/entry.test.mjs` pins the gate). Registration is fail-open via `src/skills.js` (`resourceBase` = the skill dir); `inject` carries `'skills'` (cordis blocks undeclared ctx services).
- **Layout**: plugin source under `src/` (entry `src/index.js`, plain JS, no build chain), the bundled skill under `skills/smart-spectre/`, runtime Python under `scripts/{common,spectre,snp}/`, the numpy-fallback backend under `assets/`, tests under `tests/` (bare `node --test` from the repo root; a directory argument fails on Node 24). Every script filename carries its family prefix (`common_*`, `spectre_*`, `snp_*`); keep it that way even inside subdirectories, and keep the unique basenames (a flat remote upload must not collide).
- **Script layer**: scripts are plain files spawned by the Node channel (`python <script> …`). Cross-directory imports insert `scripts/` (the parent of the script's own directory) into `sys.path` and use `from common.common_sweep_engine import …` / `from spectre.spectre_psf_parse import …`. No `__init__.py` (PEP 420 namespace packages). Worker/adjudication logic lives in the script layer; the netlist pre-check is pure JS in `src/precheck.js` (no python on the check path — the submit side needs no local python), and `scripts/spectre/spectre_checks.py` keeps the same contract as the legacy gen-script companion.
- **Language rule** (suite-wide, D-001 in the HarnessAMS repo's `docs/decisions.md`): in-plugin functionality is JS single-implementation by default; this package's Python is confined to the three sanctioned families — sweep workers and their result-parsing/diagnostic helpers (e.g. `spectre_sweep_worker.py`, `spectre_psf_parse.py`, `spectre_post_check.py`; the parser family and its diagnostic companion belong here), s-parameter numeric computing (e.g. `snp_extract.py`), and per-project user-authored assembly scripts (e.g. `gen_selfcheck_rc.py`, shipped by the top-level plugin's self-check project) — no new Python families beyond these.
- **Shared sweep engine** (`scripts/common/common_sweep_engine.py`): `@@PARAM@@` substitution (an undeclared `@@temperature@@` resolves to the default 27 degC and lands in `point_meta.defaulted_params` — a missing temperature is a warning, never a failed point; every other unknown placeholder stays in place and is recorded as unresolved), cross-product/zip combinations, point directories (`00`, `01`, …; plain decimal from 100), atomic `point_meta.json`, `sweep_progress.json` on a 30 s cadence, `.worker_started` / `.compute_node` / `.simulator` markers. Every sweep worker must keep this data contract; simulator-specific command execution and output parsing stay in each worker.
- **Tool schema**: `src/tool.js` compiles the author-facing parameter DSL into an object-rooted JSON Schema. `required` may only be `true` (omit it for optional). The old `required: false` form was the root cause of the `type: null` schema bug (dev-mount could not resolve `@deepseek-ai/dsh-tools` and registered the raw DSL); do not reintroduce it. A def may also carry `deferLoading: true` (forwarded onto the compiled tool, literal true only) and a `when` admission predicate (forwarded as `ctx.tools.register` options; kept out of the compiled tool object). `entry.test.mjs` asserts every tool's schema, required list, enum and output shape.
- **Family toggles**: `src/index.js` exports a schemastery `Config` (`spectre`/`snp`/`vsch`/`post` booleans, default `true`; changing the config hot-swaps the plugin — cordis restarts the fiber and re-registers). DSH (re-checked on 0.2.2-rc.5, unchanged) does NOT auto-render a bundle's config as settings-page switches: the plugin manager shows them only when the bundle's browser half registers the `plugins.row.config` slot (key `<package>#<row id>`); this package ships no browser half (deferred by user decision), so the toggles are edited through the profile config layer. `toolDefinitions(ctx, config)` trims a family only on explicit `false` (`!== false`, so `undefined` never trims); the `~standard` validate hook must stay a real schemastery schema — cordis `resolveConfig` calls it directly on the exported object and a plain object crashes the load. The official `tool-fs` plugin (read/write/edit booleans) is the pattern precedent.
- **Spectre channel**: `spectre_pre_check {run_dir, session_id?}` validates a hand-written run directory — the engine in `src/precheck.js` runs three independent families concurrently (language format / sweep-parameter presence / value gates) over the template named by `sweep_config.netlist_template`, resolving check parameters through builtin <- `.harnessams/check_params.json` <- `sessions.json[session_id]` (fail-open; `session_id` defaults to the effective session id — `exec.agent.id`, or a delegated subagent's topmost user-visible ancestor per `src/subagent.js` D-003 — and a managed-flow caller (the top-level suite's submit) passes it explicitly since a nested tool call's exec identity does not reliably flow). Placement: `@@P@@` on the `parameters` statement only, sole exemption `@@temperature@@` on a simulatorOptions line; an UNDECLARED `@@temperature@@` is a warning — the sweep worker substitutes the default 27 degC (recorded in `point_meta.defaulted_params`), so a missing temperature never aborts the simulation; every other undeclared placeholder stays an error. Value form: no scientific notation anywhere on a code line (SI suffixes or plain decimals — the scale can never hide in an exponent), and ideal R/C/L value positions accept a literal or a bare parameter name ONLY — expressions (`c=(cpf*1e-15)`) are errors; the shipped idiom is `c=cpf` with suffixed sweep values (`"56f"`). Ranges: R 0.1..1M ohm, C 1f..1u farad, L 0.1p..10n henry (inclusive; literals, name-referenced swept values, C/R/L-initial config names — no expression exemption; `r/c/l = 0` is the legal degenerate element: short / open), `nf`/`m` multiplier ranges (positive integers, 1..128 / 1..1000), u/n geometry suffixes. The bias gate and the include-existence checks are retired with their `bias_check`/`strict_includes` config keys. The tool description is functional only (a managed batch flow runs the same check before staging, so a pre-run is a re-run, not a pipeline step — never prescribe "check first"). Worker contract: psfascii output (`output_format: "psfascii"`), `template*.scs` (default `template.scs`; the name must match `sweep_config.netlist_template`), `@@PARAM@@`; command defaults `+lqtimeout 900`, `-maxw 5`, `-maxn 5`, `++aps` (never `+preset aps`; SPECTRE-132), `+mt`, `+logstatus`; smart timeout extends once for `Waiting for available license` and once for raw output before killing. Statuses: success (rc 0), partial (rc!=0 with raw output), failure (rc!=0 without), timeout (killed), error (spawn/template). `spectre_psf_parse.py` is a two-layer contract (breaking): the ENTRY is soft — `parse_psf_ascii_file` / `parse_psf_ascii_directory` return a `PsfResult` (status `success|partial|failure|error`, data, errors, warnings, metadata incl. per-file records; never raise on data, the batch CLI never stops on a bad point, errors ride in the outputs) and non-swept VALUE lines flatten one-level STRUCT payloads (`"M1" { "gm" .. }` / bare member sequences -> `M1:gm`-style keys; unparsable lines become warnings, never silent loss; the worker helper `scalar_signals` keeps its `{name: float}` shape and picks flattened members up); the ACCESSORS are hard — `scalar`/`vector`/`axis`/`frequency_hz` raise ValueError on rule violations (exact key, non-empty, bool excluded, finite, real, strictly increasing; every message embeds key/index so the error locates itself; `axis` composes vector + realness + monotonicity). S-parameter `sp.sp` is delegated to `snp_common.parse_psfascii` and flattened to `freq` + `s11..sNN` complex curves (both trace spellings are accepted — concatenated below ten ports, the colon form `s1:12` from ten ports up — and the flattened keys use the colon form once a port index needs two digits) (an sp analysis named other than bare `sp` is a warning — keep the instance name bare); `--raw-dir` may point directly at a standalone `.sp` file; binary PSF is unsupported by design. `spectre_checks.py` mirrors the same contract for the optional legacy gen-script path.
- **snp_***: S-parameter reading/extraction, tools-only (no UI). Purpose: convert S-parameter data to CSV for convenient calculation and extract passive-device parameters. **snp_extract takes the params CSV only**: raw `.sNp` / `sp.sp` inputs exit 2 with a convert-first hint; `snp_read` remains the three-format converter and its params CSV round trip is bit-exact (`%.17g` — 12 digits once flipped the coupled_tl eigenvalue branch and the auto port search on the scrambled fixture). **Guide-gated deferred loading**: only `snp_guide` is always declared; `snp_read`/`snp_extract` register `deferLoading: true` + a `when` predicate over a module-level `Set` of agent ids that called the guide (`src/tools/snp.js`). On `toolUpdate` routes (deepseek-flash default) activation rides `tool-addition` and preserves the KV-cache prefix; on routes without it `deferLoading` is stripped and activation resends declarations (one-time prefix break). Activation is one-way (never unset — addition-only routes drop removals), keyed by agent id string so in-process session restore keeps it; after a server restart the model self-heals by re-calling the guide. A delegated subagent inherits an ancestor's activation through SEEDED links (`src/subagent.js` `inheritsSessionState`, D-003: the inherited history prefix already carries the guide call, so the declaration reflects it; non-seeded sub-agents call the guide themselves). The guide marks activation only inside its execute (a tool call is inherently after the session's first request — required, or the deferred tools land in the declaration baseline and never activate). Wire-verified on a live instance. The registry validates execute() results against `output.schema` — a string-returning guide needs an explicit string-schema `output` override on the def (fix a8fbf42; the object-rooted default rejects strings with `"value" must be an object`). Numeric backend: numpy primary, `assets/numfallback.py` automatic pure-stdlib fallback (`SNP_FORCE_FALLBACK=1` forces it); both backends share the same upper-level code and must agree (test-asserted). Touchstone v1 ordering: 2-port files are S11,S21,S12,S22; N>2 files are row-major. The coupled_tl theory gate (default 5.0e-2) is calibrated at 4x the validated reference coupler's relative off-block residual; changing it requires recalibration notes. Known port-mapping trap: a through-pair grouping block-diagonalizes perfectly but yields non-physical modal impedances / split thetas — the physicality checks (Re(Z0) resistive-dominant, theta monotonic, theta_e ~= theta_o) must stay.- **Hard PDK isolation**: PDK paths live only in netlist/assembly-layer configuration, never in agent context; the format / dimension / ideal-value-range / multiplier checks reject at `spectre_pre_check`, before anything is submitted. The netlist layer is the only code path that touches PDK files.
- **Workspace convention (D-002)**: the family `harnessams.json` walker is RETIRED — configuration now lives per project at `<project>/.harnessams/workspace_config.json`, and nothing reads `harnessams.json` anymore (`common_workspace.py` keeps only a retirement note where the walker used to be). This package's remaining config face is `spectre_cmd`, resolved as the `--spectre-cmd` argument > the run's `sweep_config.json` `spectre_cmd` > `PATH`. `pdk_lib` never had a consumer here (PDK paths live in assembly-layer configuration only); the project's `workspace.sim_scripts_dir` still points at this package's `scripts/` tree (the suite's batch upload tree depends on it).
- **Tests**: `node --test` from the repo root (72 tests) covers tool metadata/schema/validation (including the deferred-registration shape, the guide activation semantics — own-id admission plus seeded subagent inheritance — and the bundled-skill naming gate), the subagent identity/state policy (`src/subagent.js`, shared verbatim with HarnessAMS where this repo is the source of truth; `tests/subagent.test.mjs` covers both walks, the seed rules, cycle/dead-ancestor edges and the byte-identity sync guard), the pre-check engine suite (`tests/precheck.test.mjs`: @@ placement, the no-scientific-notation rule, the undeclared-@@temperature@@ warning, sweep presence, RCL/mult value gates incl. expression rejection, zero degenerates and the session-tightened 1nF interception regression, the chain, the tool face incl. subagent resolution), recursive script parsing + filename prefixes, PSF parsing incl. the two-layer contract and STRUCT flattening (`tests/psf_parse_test.py`, fixture `tests/data/psf`), post_check collect-all diagnostics (`tests/post_check_test.py` + the tool-face spawn chain in `tests/post.test.mjs`), the Spectre worker mechanics with a fake process layer (`tests/spectre_worker_test.py`: statuses, process-group kill, max-merged timeout extensions, both-separator cmd resolution, the 30 s progress cadence during a long single point, max_parallel=0 rejection), the netlist checks (`tests/spectre_checks_test.py`), the S-parameter regression suite (`tests/data`, chained read-then-extract) and the JS tool-face contracts (snp summary/exit-1, unknown-key rejection; `tests/snp_common_test.py`: Touchstone unit-order scan, psf port-base unification, multi-digit detect_n, duplicate-frequency CSV folding, the z_to_s2 single-z0 guard). Python self-tests run as plain scripts and use `python -B` so they never write `__pycache__` into the repo. `tests/manual/compare_spectre_runs.py` is the node1 foreground-vs-batch acceptance helper (not shipped). The function-to-test map is `README.md`'s Test map section.
- **Validation**: dual-mode node1 Spectre acceptance (direct + LSF runs, 2/2 success each, recovered artifacts differing only in the PSF header `date`, identical numeric CSV rows) — reproducible with `tests/manual/compare_spectre_runs.py`.
- Runtime artifacts (netlists, simulation outputs, report intermediates) are written into the project's run directories (`<run dir>/<NN>/`), never committed; scripts take explicit paths from the tool arguments (project_dir / run_dir / work_dir) to survive CWD drift.
- Content gates — a local pre-commit hook under `.git/hooks/` (untracked; recreate it after a fresh clone) scans the staged index and refuses the commit when a scanner itself fails. (1) **Fixture hygiene**: tests and docs never carry real cluster account tokens, private-net IPs, local drive paths or the dev machine name — use the neutral placeholders (`op`, `test_user`, documentation-range `192.0.2.x` IPs, `D:/proj/...`);  (2) **English-only content**: no CJK scripts or fullwidth punctuation anywhere in the staged tree (docs, comments, tests, skill text) and no non-ASCII file names. The gate's only built-in exception is a bilingual UI (`src/locale/zh.json` and the `'key': 'text',` zh dictionary lines of a `src/client.js`); this package ships no browser half, so in practice there is none — write any such character as a `\uXXXX` escape.
- Commits: local commits are at the agent's discretion (no per-commit approval needed); **pushing is always manual** — automated flows must never push. Messages in English (`<verb> <scope>: <summary>`), one topic per commit.
