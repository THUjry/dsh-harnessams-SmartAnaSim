# AGENTS.md — HarnessAMS-SmartAnaSim

> Rules for AI agents and human maintainers working in this repo. Read this file before changing anything here. This repo keeps English-only, self-contained content (no references to files outside the repo).

- Package `dsh-harnessams-smart-ana-sim` / row id `harnessams-smart-ana-sim`; `engines.dsh` locks the verified DSH version; `@deepseek-ai/dsh-*` dependencies are double-written as peer + dev with the same range.
- Repo layout: plugin source under `src/` (entry `src/index.js`, plain JS, no build chain), runtime Python under `scripts/`, the numpy-fallback backend under `assets/`, starter tests under `tests/` (bare `node --test` from the repo root; a directory argument fails on Node 24; `tests/data/` holds anonymized real EM regression data and is committed), root-level meta files (CHANGELOG / SECURITY / PUBLISH) per the DSH plugin ecosystem conventions.
- snp_* scripts (2026-10-30): S-parameter reading/extraction, tools-only (no UI). Numeric backend: numpy is the primary path — the user's system python is expected to provide it — and `assets/numfallback.py` is the automatic pure-stdlib fallback (`SNP_FORCE_FALLBACK=1` forces it for testing); both backends share the same upper-level code and must agree (test-asserted). Touchstone v1 ordering: 2-port files are S11,S21,S12,S22; N>2 files are row-major. The coupled_tl theory gate (default 5.0e-2) is calibrated at 4x the validated reference coupler's relative off-block residual (tests/data); changing it requires recalibration notes. Known port-mapping trap: a through-pair grouping block-diagonalizes perfectly but yields non-physical modal impedances / split thetas — the physicality checks (Re(Z0) resistive-dominant, theta monotonic, theta_e ~= theta_o) must stay.
- **Hard PDK isolation**: PDK paths live only in assembly-layer configuration, never in agent context; the format / dimension / bias<Vdd checks reject at the assembly layer, before the simulator. The assembly layer is the only code path that touches PDK files.
- **Safety by default**: destructive operations move paths to the trash folder instead of deleting; the best point is persisted to `bestPoints.json` immediately as it is found.
- Batch skeleton invariants: `@@PARAM@@` template substitution, per-point `point_meta.json` (atomic writes), a `sweep_progress.json` aggregate updated on a 30s cadence, and combination generation via cross-product (or zip for equal-length lists).
- Dashboard hard rules (keep them when editing `gen_sweep_report.py`): `var ROUND_DATA` (never const), `<script>` tag loading of round data, `?v=` cache-bust, utf-8-sig for the HTML with plain-utf-8 data JS, `el.on` handlers re-bound after every `Plotly.newPlot`, native DOM handlers bound exactly once, per-section try/catch isolation. There is no bundler safety net: one JavaScript syntax error silently blanks the whole self-contained page — test-render after edits.
- Reports load Plotly from a **single workspace-level copy** (`<workspace_root>/assets/plotly.min.js`, workspace root = the directory holding `harnessams.json`): `gen_sweep_report.py` seeds it on demand via `--plotly`, four candidates probed at each ancestor directory (`assets/plotly.min.js`, `src/assets/plotly.min.js`, `node_modules/dsh-harnessams/assets/plotly.min.js`, `dsh-harnessams/assets/plotly.min.js`), or the workspace `plotly_asset` field (refresh on size mismatch), and every report references it with a workspace-relative `src`; the CDN is the fallback (`--plotly-cdn` forces it). Do not duplicate `plotly.min.js` inside this package — the master copy lives inside the `dsh-harnessams` package in the top-level HarnessAMS repo and ships with its tarball. Decision record: top-level repo `docs/decisions.md` (D-001).
- sky130 conventions: use the fossi-foundation **continuous** `combined_models` models (the frozen google build fails to parse under ngspice-47, and the binned top-level models impose a w<=100 um limit); w/l are written internally as bare um values (the model library sets `scale=1u`); user input with u/n suffixes is normalized at the assembly layer; MOS instances use the X prefix; MC's `.option seed` precedes `.lib`.
- Plugin architecture: the Node entry (`src/index.js`) is only the channel — tool executes spawn the plain Python scripts under `scripts/`; assembly/check/adjudication logic lives entirely in the script layer (no build step, system Python only).
- Workspace convention: a `harnessams.json` is discovered by walking upward (bare form, or inside `harnessams-workspace/`); relative path fields resolve against the config file's directory (this is what lets a checked-in example workspace work for any clone path).
- Runtime artifacts (netlists, simulation outputs, report intermediates) are written into the demo project's run directories (`sweep/Round*/top/<NN>/`), never committed; scripts resolve paths from the workspace `harnessams.json` to survive CWD drift.
- Commits require an explicit user request or authorization.
