# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow semver.

## [Unreleased]

### Added

- `post_check` (2026-11-25, the sanctioned tool-shaped exception to the script-face ruling): an on-demand data-integrity diagnostic for when sweep results look wrong, empty or incomplete. Collect-style over a sweep run directory (`work_dir`) or one point's raw directory (`raw_dir`): every point is scanned (bad points reported, never skipped), the parser's strict accessor rules are inverted into catch-and-enumerate (coverage vs `sweep_progress.json`, exactly-one `*.raw` per point, parse errors, axis realness/monotonicity counted exhaustively, NaN delta gaps, `point_meta.signals` scalar rules, parser-dropped VALUE lines, errlog tails) and the result is one classified JSON report with per-check counts and a capped issue list — zero file artifacts. Pure JS orchestration in `src/tools/post.js`; every check lives in `scripts/spectre/spectre_post_check.py` (argparse owns the exactly-one input rule). Family toggle `post` (default true); tool surface 6 -> 7.

### Changed

- `spectre_psf_parse.py` is rebuilt around a two-layer contract (2026-11-25, BREAKING for library consumers — the CLI flags and output files stay compatible, the JSON payload shape and the return types change): the ENTRY is soft — `parse_psf_ascii_file` / `parse_psf_ascii_directory` return a `PsfResult` (status `success|partial|failure|error`, data, errors, warnings, metadata incl. per-file records) instead of a bare dict / `{}` on failure, the batch CLI records EVERY point in the index (failed points with their errors, never skipped), and per-point payloads carry status/errors/warnings. Non-swept VALUE lines now flatten one-level STRUCT payloads (`"M1" { "gm" .. "gds" .. }` or the bare member sequence -> `M1:gm`, `M1:gds`); lines that fit no shape become warnings instead of silent loss, and the worker helper `scalar_signals` picks the flattened members up (same `{name: float}` shape). New strict accessors for fail-loud consumers — `scalar` / `vector` / `axis` / `frequency_hz` raise ValueError on rule violations (exact key, non-empty, bool excluded, finite, real, strictly increasing; every message embeds key/index; `axis` composes vector + realness + monotonicity). An sp analysis named other than bare `sp` now warns by name (keep the instance name bare); `--raw-dir` may point directly at a standalone `.sp` psfascii file (outputs land beside it). Tests 61 -> 66 (two-layer contract, STRUCT flattening, accessors, collect-all diagnostics, tool-face spawn chain).
- `spectre_assemble` is retired and replaced by `spectre_pre_check` (2026-11-25): after the scan migration the assembly tool was a thin shell around the project's `gen_*.py`, while the recommended workflow already hand-writes the run directory. `spectre_pre_check` is the pure-JS gate for those hand-written netlists — language format (`simulator lang=spectre`, SPICE-directive rejection, LF/ASCII, `@@P@@` placement on the parameters statement only with `@@temperature@@` on a simulatorOptions line as the single exemption), sweep-parameter presence (both directions), and the value gates (ideal R/C/L ranges, `nf`/`m` multiplier ranges, u/n geometry suffixes) resolved through the check-parameter chain. The HarnessAMS `batch_submit` tool calls it automatically before staging; `no_pre_check: true` waives it after review. `src/projects.js` (the assembly bridge) is deleted; `scripts/spectre/spectre_checks.py` stays as the legacy gen-script companion on the same contract.
- Check-parameter table re-shaped (2026-11-25): `bias_check` and `strict_includes` are retired with their check families (the bias gate and the include-existence checks are gone), and a `mult` table (`nf: [1, 128]`, `m: [1, 1000]`, positive integers) joins `rcl` and `unit_check`. Legacy keys in existing check_params.json / sessions.json files are ignored on read; `common_units.py` drops the dead `norm_current` / `check_bias_lt_vdd` helpers. Tests 47 -> 61 (precheck engine suite; entry/schema updates).

- snp family is now guide-gated with deferred loading: `snp_read` / `snp_extract` register with `deferLoading: true` plus a `when` admission predicate, so they stay out of the model-facing declarations until the new always-resident `snp_guide` tool is called (its execute marks the calling agent and returns the usage flow). On `toolUpdate` routes (deepseek-flash default) activation rides `tool-addition` and preserves the KV-cache prefix (~745 declaration tokens saved for spectre-only sessions); on routes without it the `when` gating still applies and activation resends the declarations once. Activation is one-way per session, keyed by agent id (survives in-process session restore; server restart self-heals via a guide re-call; sub-agents call the guide themselves). `src/tool.js` forwards def-level `deferLoading` / `when` through the local compiler. Tests 31 → 33 (deferred-registration shape + guide activation semantics).
- Wire-verified on a live 0.2.2-rc.3 dev-mount instance with deepseek-flash (2026-11-18): first request declares 48 tools without snp_*; after the guide call the declaration set grows to 50 with two `defer_loading` entries plus exactly one `tool-addition` pair, and cacheReadTokens never drops at the addition step (12928 → 24192 → 24320 → …). In-process session reopen keeps activation; after a server restart a direct `snp_read` call fails with `unknown tool` (the loop writes a `tool-removal` pair and rebases once — the documented addition-only boundary) before a guide re-call heals it with a fresh addition pair. The same run surfaced that the registry validates execute() results against `output.schema`: a string-returning guide needs an explicit string-schema output override (fixed in this release).

### Fixed

- Robustness backlog cleared (2026-11-26, the 20 still-standing items of the shelved SAS robustness ledger — see the top-level repo's dev/todo and wave notes). Worker: a timeout now kills the whole process group (`start_new_session` + `killpg`, so the csh-wrapped Spectre no longer survives as a license-holding orphan), the two timeout extensions merge with `max` instead of overwriting, `resolve_spectre_cmd` accepts forward-slash relative paths on Windows, `sweep_progress.json` keeps its documented 30 s cadence during a long single point (the completion loop wakes on `wait(..., FIRST_COMPLETED)`), and `max_parallel=0` is an explicit startup error instead of a silent fallback to 4. Parser: the CSV `sweep_value` column carries the real sweep axis (time/freq, else the first list-valued signal — hardcoded time/freq left it empty for AC/DC sweeps; the axis keeps its rows, which selfcheck_verify consumes as a curve, and the per-row lookup moved out of the inner loop); non-finite scalars become `null` like list values (an inf/NaN scalar used to crash the whole batch CLI through `allow_nan=False`); a write failure on one point folds into `psf_index.json` instead of killing the batch; point directories sort numerically ("100" after "99"). Units/checks: positivity is judged after `fmt_num` (sub-1e-12 positives used to emit as 0); `norm_count`'s doc matches its `>= minimum` behavior; a failed `format()` substitution warns on stderr. snp: the Touchstone option-line unit scan is position-independent with a non-standard-order warning; psfascii port references unify on the file-declared base (EMX's 1-based `port<k>` no longer lands one port high when the `num` field is absent) and `detect_n` splits even digit runs so ports >= 10 are detectable; duplicate frequency blocks in a params CSV keep the first copy with a warning; `z_to_s2` broadcasts a single z0 to all ports (IndexError before); an unequal per-port z0 zref fallback to 50 ohm warns (it feeds Gmax normalization); out-of-band `--freq-hz` clamping and type-irrelevant flags warn on stderr; physicality warnings moved to stderr (stdout keeps result lines only); `_majority_positive` renamed to `_mostly_positive` to say what the >= 70% bar actually is. JS tools: `snp_extract` rejects unknown parameter keys with the valid list (they used to become invented CLI flags), and `runPython` retries under `python3` once on ENOENT. Tests 70 → 73 (`tests/snp_common_test.py` new; worker/psf/snp suites extended).

## [0.1.0] - 2026-11-10

Initial release (stage 1 scope).

### Added

- DSH plugin entry `dsh-harnessams-smart-ana-sim` (row id `harnessams-smart-ana-sim`) exposing five tools: `spectre_assemble`, `spectre_run_sweep`, `spectre_parse`, `snp_read`, `snp_extract`. Source under `src/` (plain JS, no build chain); the generic remote batch channel and the sweep-result analysis tools belong to the top-level `dsh-harnessams` plugin — this package stays simulator-specific.
- Spectre channel: code-driven netlist assembly with hard PDK isolation — `.scs` format checks (placeholders, include paths, unit-suffix rule, ideal R/C/L value ranges, bias < Vdd), `@@PARAM@@` templating, per-point `point_meta.json` + `sweep_progress.json` progress, psfascii output with smart license/output timeout extensions, and PSF ASCII parsing (swept/delta/complex plus non-swept `.info` scalars). Overall sweep timeout defaults to 1200 s.
- S-parameter tools (local, tools-only by design — no UI):
  - `snp_read` — parse Touchstone v1 (.s1p..sNp) / Spectre psfascii sp.sp (S/Y/Z paramtype) / params CSV (round-trippable); dump per-frequency S/Z/Y curve CSV with a metadata header, plus header info, band stats, reciprocity diagnostic and max |Sij|.
  - `snp_extract` — device parameter extraction from the same inputs: transformer (L1/L2/Q1/Q2/k, two SRFs, Gmax; 2/3/4/5/6 ports incl. center taps), inductor (L/Q/SRF), tl (Zc, gamma*l, theta; 2-port or 4-port differential), coupled_tl (modal Z0e/Z0o/theta/k, theory gate on the off-block residual). Missing or unphysical port mappings are auto-adjusted against physicality checks; every result echoes a `port_plan` for confirmation.
- Plain-Python pipeline shipped under `scripts/{common,spectre,snp}/` (no build step, system Python only): the family workers plus `common_sweep_engine.py` / `common_units.py` / `common_workspace.py`, `spectre_psf_parse.py`, `spectre_checks.py`, `snp_common.py` / `snp_read.py` / `snp_extract.py`. Numeric backend is numpy with the bundled pure-stdlib `assets/numfallback.py` fallback (forced by `SNP_FORCE_FALLBACK=1`).
- Family toggles via the schemastery `Config` (`spectre` / `snp` booleans, default `true`): `apply(ctx, config)` registers only the enabled families; changes hot-swap the plugin.
- Plotly delivery: reports reference a single workspace-level `<workspace_root>/assets/plotly.min.js` seeded on demand (ancestor-probed candidates or the workspace `plotly_asset` field); the CDN is the fallback. The master copy lives in the top-level `dsh-harnessams` package — this package intentionally ships none (decision D-013 in the top-level repo).
- Workspace convention: `harnessams.json` is discovered by walking upward (bare form, or inside `harnessams-workspace/`); relative path fields resolve against the config file's directory; `trash_dir` is honored when present.
- Tests under `tests/` (`node --test` from the repo root): tool schema/registration, script parsing + naming, PSF parsing, Spectre worker statuses with a fake process layer, the S-parameter regression suite (synthetic round-trip fixtures plus anonymized real EM data), and the RCL range-check scenarios.
